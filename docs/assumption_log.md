# Assumption log

Every modelling simplification, with the reason and what replaces it later. Units: GBP thousands.

| # | Area | Assumption | Why | Revisit |
|---|---|---|---|---|
| 1 | Scenarios | `Inputs_Scenarios` holds values; `Inputs_Drivers` column C pulls the live column with `INDEX(..., inp_scen_idx)`. The named range `inp_*` points at that live cell. | One selector drives the whole model. | Website writes custom values into the **Custom** column, not the live cell. |
| 2 | Growth | New-logo volume is an input per month with an annual growth rate. | Stands in for sales capacity x ramp until the capacity model is built. | Phase 2: sales capacity and ramp. |
| 3 | ARR | Contraction is netted into gross churn. No separate contraction line. | Keeps the bridge to four lines. | Phase 2 if needed. |
| 4 | ARR | Logo churn rate equals the ARR churn rate for each segment. | One churn driver per segment. | Phase 2. |
| 5 | Billing | Both segments are billed annually upfront. Renewal invoice = invoice 12 months earlier x (1 + expansion - churn). Opening-year invoices are spread evenly: opening ARR / 12 per month. | Gives real billing history, so deferred revenue is derived, not plugged. | Add multi-year Enterprise terms. |
| 6 | Rev rec | Each annual invoice is recognised over 12 months starting in the month invoiced (IFRS 15 ratable). Revenue therefore lags ARR slightly. See memo row `Subscription revenue / (closing ARR / 12)`. | Matches how a subscription is recognised. | n/a |
| 7 | Implementation | Fee = % of new Enterprise ACV, billed at signing, recognised over 3 months, as a separate performance obligation. | Shows the two-obligation split. | n/a |
| 8 | Opening deferred revenue | Subscription balance = SUMPRODUCT of the 12 historic invoices and their unexpired share. Implementation opening balance is an input (0). | Consistent with the billing history. | n/a |
| 9 | Receivables | Receivables = this month's billings x min(1, DSO/30) + last month's billings x clamp((DSO-30)/30). Valid for DSO 0-60 (cap at 90 in the input range gives full two-month cover). | Portable, no lag functions. | n/a |
| 10 | Payables | Payables = non-payroll spend x DPO / 30. DPO limited to 0-30. | Simple, portable. | n/a |
| 11 | Costs | Commission is expensed as incurred. | Phase 2 capitalises it in `Contract_Costs` (IFRS 15 incremental costs of obtaining a contract). | **Phase 2.** |
| 12 | PP&E | Depreciation = opening NBV / `inp_dep_life` (declining balance). Capex = % of revenue. | Avoids an asset-by-asset register. | n/a |
| 13 | Interest | Interest income is earned on the **prior-period** closing cash balance. | Avoids circularity (build principle 5). | Keep. |
| 14 | Tax | Tax = 25% of positive profit before tax. No loss carry-forward, no tax payable balance (paid in month). | MVP; the company is loss-making, so tax is nil. | Add NOLs when profitable. |
| 15 | Financing | No debt and no equity raises. Cash is the only funding source. | MVP. The `Cash never negative` check turns red if the plan runs out of cash. | Phase 3 (deal funding). |
| 16 | Opening equity | Opening equity = opening assets - opening liabilities (a balancing figure at the opening date only). Every later period must balance without a plug. | There is no opening share-capital history to model. | n/a |
| 17 | Metrics | NRR and GRR are annualised from each month's flows: `(1 + net flow / opening ARR)^12`. | Always available, even before month 12. | Compare with a cohort-based NRR in Phase 2. |
| 18 | Metrics | CAC payback uses fully loaded S&M spend over (new + expansion ARR) x gross margin. LTV uses blended ARR per customer. | Standard blended definitions. | n/a |
| 19 | Time axis | Columns C:M (months -11 to -1) hold opening-year billing history on every tab and are grouped (hidden), except on `Rev_Rec`. | Lets the 12-month lag use one consistent formula in every forecast column, with no `OFFSET`. | n/a |
| 20 | Contract costs | All commission earned is capitalised (toggle `inp_capitalise_commission`). Amortisation = opening asset / `inp_cc_life` (declining balance), not cohort by cohort. Opening asset is an input. | Approximates amortisation over the expected customer life without a cohort schedule. | Cohort amortisation if a precise life is needed. |
| 21 | Metrics | CAC uses cash S&M (P&L S&M + capitalised commission - amortisation), so capitalising commission does not flatter CAC. | CAC should reflect cash spent to win customers. | n/a |
| 22 | Annual columns | "Opening" rows show the first month's opening value in each year column. (Fixed in v0.2: v0.1 showed 0 for FY1.) | Bug found while building the budget bridge. | n/a |
| 23 | Budget | The board budget is synthetic: typed in a different layout (GBP m, quarters, costs negative). It was written to differ plausibly from the Base forecast. | Shows mapping of a budget you don't own. | n/a |
| 24 | Variance bridges | Revenue bridge applies a mid-year convention (0.5 x each ARR effect). The residual is labelled "timing / other". ARR bridge is exact: volume = (customers_f - customers_b) x ACV_b, price = customers_f x (ACV_f - ACV_b). | Revenue cannot be split exactly from annual ARR flows. | n/a |
| 25 | Long-term view | Years 3-5 grow new-logo ARR at `inp_lt_newarr_growth`, step the expansion rate up, hold churn, and step opex ratios down. Cash is simplified: no interest, no full balance sheet; working-capital balances held as % of ARR. | Driver-based view for a board horizon. | Full annual three statements if needed. |
| 26 | Static tables | `Lever_Analysis`, `Sensitivity` and the Base/Upside/Downside block on `Business_Review` hold engine-run values (grey italic) because neither Excel nor Sheets can re-run a whole model per cell without data tables. `validation/snapshots.py` regenerates them. The `Checks` tab fails if they no longer match the live Base model. | Keeps the workbook portable; makes staleness visible instead of silent. | Phase 4/7: website recalculates these live. |
| 27 | M&A: timing | The deal closes at the model's opening date (t=0), so the pro-forma consolidates from month 1. | Keeps the combined model on the same time axis as Northgate. | Mid-year closing, completion accounts. |
| 28 | M&A: Vaultline | Vaultline costs are percentages of revenue; ARR and billings mirror Northgate's mechanics (annual upfront, ratable). It has no debt. | Simplified standalone model. | Detailed cost build in diligence. |
| 29 | M&A: funding | Equity price = EV + cash acquired. Funded by a bullet term loan (`inp_ma_debt`) and Northgate cash. Interest on the prior-period loan balance. Interest income on cash paid out is removed (prior-period basis). | Non-circular. | Revolving facility, equity raise. |
| 30 | M&A: PPA | Customer relationships and technology are % of EV (illustrative). DTL = tax rate x intangibles. Acquired deferred revenue is written down by `inp_ma_dr_haircut` under IFRS 3 and unwinds evenly over 12 months; the US GAAP column carries it over at book. Transaction costs are expensed in month 1. | Shows the IFRS 3 vs ASU 2021-08 difference. | Valuation specialist inputs. |
| 31 | M&A: eliminations | One intercompany contract is eliminated (revenue and cost). No intercompany balances remain at period ends. | Shows consolidation mechanics. | n/a |
| 32 | M&A: synergies | Cross-sell ARR ramps linearly from `inp_ma_syn_start`; it never churns and revenue is average ARR / 12 at `inp_ma_syn_margin` contribution. Cost synergies ramp the same way. Synergy cash = synergy P&L (no working capital). `inp_ma_syn_achieved` scales synergies, not integration costs. | Transparent and linear, so break-even synergies have a closed form. | Phase 4 review. |
| 33 | M&A: valuation | DCF uses unlevered free cash flow, end-year discounting, Gordon-growth terminal value. Years 3-5 fade ARR growth by `inp_ma_fade` and hold the year-2 cash-flow margin. Synergies and integration costs are taxed at the standard rate and discounted at the same WACC. Comps are synthetic and fictitious; the mid-point is the average, not the median. | Method demonstration. | n/a |
| 34 | M&A: returns | Value created = standalone DCF + PV of achieved synergies - PV of integration - EV paid - transaction costs. Payback is undiscounted cash recovery over 5 years. Deal-outcome scenario table is a static engine-run snapshot. | Clear decision metric. | n/a |
| 35 | Checks | One global tolerance (`chk_tol`, 0.01 GBP k) governs all tie-out checks. Sign checks and range checks have zero tolerance. | One visible setting instead of scattered numbers. | n/a |
| 36 | Checks | Outlier warnings compare each month with the previous one against a blue threshold (15% for revenue, opex, cost of revenue and deferred revenue; 10% ARR; 5% headcount; 2 pts gross margin; 5 pts EBITDA margin). They prompt a review and do not feed the master flag. | A legitimate step change (a price rise, a hiring wave) should not fail the model. | Tune thresholds by series. |
| 37 | Thresholds | Policy thresholds are visible blue inputs, not literals in formulas: risk flags on `Business_Review`, the on-budget band on `Budget_vs_Forecast`, the DCF bands (`inp_ma_wacc_band`, `inp_ma_tg_band`) and the funding headroom flag on `MA_Returns`. | Found by the validation script's literal scan. | n/a |
| 38 | Validation | The independent Python model reproduces the Northgate model and the goodwill calculation only. It was written from the same understanding of the business, so it tests wiring and arithmetic, not shared conceptual errors. | Scope of the independent check. | Phase 5 manual rebuild by the model owner. |
| 39 | Web contract | The website reads only the `out_*` names on `Outputs_Web` (links only) and writes only `inp_*` names. A scenario-driven input is changed by writing to its Custom column and selecting Custom. | One stable interface; the site never reaches into calculation tabs. | Phase 6 loads `model/named_ranges.json`. |
| 40 | Portability | No array arithmetic anywhere: month-on-month outlier flags and the ARR segment check use plain helper rows, and `SUMPRODUCT` is only ever called with two ranges. | HyperFormula disables array arithmetic by default; helper rows work in every engine. | Verify by loading in HyperFormula (Phase 6). |
| 41 | Verification | The hand verification in Phase 5 is a task for the model owner. The kit provides inputs, targets and the logic in words, deliberately not the formulas. | Build principle 10: every formula is understood by a person. | Record the outcome in `tests/manual_verification.md`. |
| 42 | Web engine | The site runs the workbook with HyperFormula (GPL-3.0). Single-cell names are replaced by direct addresses at load time because HyperFormula named expressions fail on cells that hold formulas. | Found by the engine test. | Re-test if HyperFormula is upgraded. |
| 43 | Web copy | `model/keel_saas_model_web.xlsx` is the same workbook without the football-field chart. The site loads it and ExcelJS writes the download from it. | ExcelJS cannot read openpyxl chart drawings. The site draws its own football field. | Replace ExcelJS or patch the zip if the chart must survive the download. |
| 44 | Input editing | Editing a scenario-driven input copies the viewed scenario into the Custom column, writes the value, and selects Custom. "Changed from Base" compares each live value with the Base column (or the loaded value for static inputs). | One consistent rule for presets and custom cases. | Saved scenarios (next phase). |
| 45 | Recalculation timing | Recalculation runs 300 ms after the last keystroke (debounce). | Brief requirement 5.4. | n/a |
| 46 | What-if engine | Planner and sensitivity tools run on a second, lean HyperFormula instance (no `Outputs_Web`), built on first use. A session sets every varied input in one batch and restores the instance afterwards; the page's own model is never touched. | 49 recalculations in about 3.8 s instead of about 5.2 s. | n/a |
| 47 | Tornado | Flexes 27 drivers (all scenario-driven inputs plus eight cost, price and valuation inputs) by the same percentage, one at a time, from the current inputs. A driver whose value is 0 is listed as not flexed; values are limited to the input's allowed range and flagged when that happens. | One-at-a-time ranking, not an interaction analysis. | n/a |
| 48 | Scenario bridge | Drivers are applied in registry order and each contribution is measured after the ones above it. The split depends on that order; the total is exact. Beyond 12 changed drivers the smallest are grouped. | Brief 5.5. | n/a |
| 49 | Goal seek | Bisection inside the input's allowed range; reports no solution when the output does not cross the target between the limits. A runway with no cash burn counts as an unlimited number of months. | Simple and transparent; may miss other solutions if the relationship is not monotonic. | n/a |
| 50 | Saved scenarios | Up to four, stored in this browser only as the list of inputs that differ from Base; saving is disabled when storage is blocked. | Brief 5.5 and acceptance test 7. | n/a |
